Why our listings expire: the 60-day rule that keeps the board honest

OpenJob · November 25, 2026

Board

I maintain OpenJob — and I put an expiry date on every listing on purpose.

The rule is short: a job on OpenJob lasts 60 days from the day it was posted, or from the day it was last renewed. A talent profile lasts 180 days. Company pages never expire. After that, the listing's time is up unless its owner renews it — and renewal is a deliberate act, not a refresh button: the owner opens a pull request that edits the existing file, keeps the original posted date, and sets renewed to the day the pull request opens.

That is a feature, not a limitation. Most job boards accumulate. A posting goes up, the role fills or the budget moves, and the post sits there for years, collecting applications nobody will ever read. On OpenJob, a listing that nobody stands behind any more simply leaves the board. What you see is what an employer or a person is still willing to put their name to, this quarter.

Renewal is a signal, not a formality

Renewal means something because only the owner can do it. A job can only be added, edited, or closed by the owners of its company page, and a talent profile only by the person it belongs to. A pull request that touches a post auto-merges only when its author owns every file it changes. So when a job shows a recent renewed date, it means the employer came back and said, yes, we are still hiring for this — not that a scraper re-fetched the page.

Owners can also set a post to expire sooner than the cap — a 30-day posting for a role that needs filling fast, for example — but never later. The 60-day and 180-day caps are the ceiling, not a suggestion: the board's rules do not let a listing promise more shelf life than that.

The same rule, for people

Talent profiles get the longer clock — 180 days — because a person's availability changes more slowly than a single requisition. The same principle applies: after 180 days without renewal, the profile expires. Profiles published through the anonymous API come with a private deletion token, shown once when the profile is created; the owner can delete the profile with that token at any time. One honest limit, stated up front: deleting a profile removes it from the board, but it cannot recall copies that were already downloaded.

Publishing a profile needs no account and no API key — the API and the remote MCP endpoint accept it, and the GitHub pull-request workflow is the alternative. No email and no phone number ever appear in a profile, and a job may show at most one hiring address, and only when its domain matches the company's own website.

What expiry does — and does not — cover

Here is the honest boundary. The expiry rule governs the native board: the jobs and profiles posted to OpenJob itself, where 26 companies have pages today. It does not govern the indexed dataset — the 33,440 rows pulled from employer ATS boards (manifest generated 2026-11-24T23:22:20Z), which carry the posted dates the employers themselves state. Some of those dates go back to 2019, and we do not rewrite them.

So we measure the indexed half honestly instead of pretending the rule covers it. Our November 23 re-run — same six shards, same definitions, 5,438 sampled rows — found 42.1% fresh (2,290 rows posted in the last 60 days), 40.8% on the ATS-weighted estimate, about 13,650 roles — the honest live figure we quote as about 14,000. The native half expires by rule; the indexed half is counted in the open. Either way, the number a job seeker should plan around is ~14,000, never 33,440. The full count is in We counted our own index honestly and its Chinese version, and the shape of the fresh half is in The live half of the index.

The point of the expiry rule is that the board cannot quietly become an archive. Every listing on it is either recent, or recently renewed by someone who owns it. That is a small rule with a large effect: it is the mechanism that keeps the live half honest.

How it works, in brief

  • Jobs: 60 days from posted or renewed. Renew by editing the existing file in a new pull request; keep posted unchanged and set renewed to the day you open the pull request.
  • Talent profiles: 180 days. API profiles return a private deletion token once — save it; it is the way to delete the profile later.
  • Company pages: no expiry. A new company page is reviewed once; after that, only its owners can edit it.
  • Caps: you may set expires sooner on a job or talent post, never later than the cap. posted and expires are dates in YYYY-MM-DD form.
  • Sources: the rules above are from https://openjob.softprobe.ai/llms.txt and the repository's AGENTS.md (both read November 25, 2026). The freshness figures are from the November 23 snapshot recompute — sample 5,438 rows from shards 0, 7, 14, 20, 27, 33, both SHA-256 checksums verified; full method in How we count.
  • Indexed ≠ recruited. Every dataset number describes rows indexed from employer ATS boards. OpenJob did not recruit these employers; the employers own the text.
