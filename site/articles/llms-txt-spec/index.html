llms.txt for job boards: a short spec

OpenJob · November 22, 2026

Board

Every job board on the internet is built for human eyeballs: infinite scroll, faceted search, SEO pages, tracking pixels. None of that is readable by the thing now doing the job search — your agent.

llms.txt is a small Markdown file at the root of a site, written for language models instead of browsers. It tells an agent what the site is, what it offers, and how to use it. OpenJob publishes one at https://openjob.softprobe.ai/llms.txt, and it is the whole product: paste one prompt into any agent and it can find you a job.

Read https://openjob.softprobe.ai/llms.txt and follow it. Find me a job.

This is a proposal for what a job board's llms.txt should contain, so any board can adopt it. OpenJob is the reference implementation — the spec belongs to whoever uses it.

1. What the board is, in one paragraph

Name, scope, and who it is for. No marketing copy — the agent needs facts: what kinds of jobs, what geography, what language coverage.

Example (OpenJob): "A public job database for AI agents. 33,430 rows indexed from employers' own careers pages; ~14,000 posted in the last 60 days. English and Chinese. No account, no tracking."

2. The honest counts

A board's llms.txt must state, separately:

  • Total rows vs rows posted in the last 60 days. The first is the cumulative index; the second is the live number. Conflating them is the oldest trick in job boards, and agents should not be tricked.
  • Expiry policy. How long a posting lives before it drops out (OpenJob: jobs 60 days, talent profiles 180 days).
  • Concentration. What share of rows comes from the top 10 employers (OpenJob: 48.2%). An agent matching a candidate should know when it is searching a concentrated index.

3. How to search (the machine-readable paths)

  • The index location: where the full dataset lives and how it is sharded (OpenJob: https://openjob.softprobe.ai/api/data/manifest.json, 34 shards of 1,000 rows, JSONL, checksummed).
  • The per-row fields an agent can trust: title, headline (employer), location, posted, employment_type, salary_text, ats, source_url, apply. And the fields it must never invent: there is no contact unless the row carries one.
  • The canonical link rule: the job link is source_url — the employer's own page. Indexed rows have no permalink of the board's own; the board never pretends otherwise.

4. How to apply, post, and add a profile

  • Apply: candidates apply on the employer's own page, never through the board.
  • Post a job: the exact path (OpenJob: one Markdown file, one pull request, validated and auto-merged; the file format and required front matter are in CONTRIBUTING.md under "Post a job").
  • Add a talent profile: the exact path, the expiry, and the delete mechanism (OpenJob: 180 days, delete token).

5. What the board will not do

This section matters most. An agent needs to know the board's limits before it starts hallucinating around them:

  • No ranking, no matching of its own — bring your own matching method.
  • No invented contacts, salaries, or links. If a field is absent, it is absent.
  • No tracking, no accounts, no personal data collection.
  • Indexed is not endorsed: the board links to employers; it does not vouch for them.

6. The reference implementation

OpenJob's llms.txt is live at https://openjob.softprobe.ai/llms.txt, and the repo is github.com/softprobe/openjob (MIT code, CC BY 4.0 posts). Steal the format, keep the honesty rules, and your board works with every agent that already knows how to read llms.txt.

If the format spreads, every agent gets better at job search — and OpenJob is the reference. That is the whole bet: a standard that compounds into links, and a reference implementation that earns them.
